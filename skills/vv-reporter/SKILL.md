# VV Reporter スキル

このスキルは、Claudeが作業中に重要なタイミングで進捗状況や結果をvvsayコマンド（VOICEVOX）を使って音声で報告することを可能にします。
報告文は、vvsay に設定されている読み上げキャラクターの口調で作ります。

## 現在のキャラクターと口調

以下はスキルの読み込み時に vvsay の設定（`default_preset`）から自動で取得したものです。報告文はこの口調で作ってください。

!`bash ${CLAUDE_SKILL_DIR}/scripts/voice-profile.sh`

## いつこのスキルを使うか

作業内容を細かく報告するため、以下のような状況で積極的に音声報告を行います：

1. **タスク開始時** - 新しいタスクに取り組み始めるとき
2. **サブタスク開始時** - 個別のステップを開始するとき（コンパイル開始、テスト実行開始など）
3. **進捗報告** - 各ステップが完了したとき（小さなステップでも報告）
4. **ファイル操作** - ファイルの作成、読み込み、書き込みなど
5. **タスク完了時** - 全ての作業が完了したとき
6. **エラー発生時** - 問題が発生したとき
7. **状態変化** - システムやアプリケーションの状態が変わったとき

## 報告文作成のガイドライン

### 基本原則

1. **頻繁に報告**: 小さなステップごとに報告する。1つの大きなタスクを複数の小さな報告に分割する
2. **簡潔な主文 + 補足**: まず1文10〜20文字程度で簡潔に述べ、補足があれば100字程度で追加する
   - 補足の内容: 「これから行うこと」「行ったことの要約」「状況の説明」「考えや推測」
3. **具体的な内容を含める**: 「タスク」などの抽象的な表現は避け、具体的な作業内容を述べる（例: 「タスクを開始します」→「ビルドを開始します」）
4. **事実を淡々と述べる**: 感情表現は控えめに。起きた事実を中心に報告する
5. **明確に**: 何が起きたのか、何をしているのかを明確に伝える
6. **自然な日本語**: VOICEVOXは日本語に特化しているため、自然な日本語を使用
7. **英語はカタカナに変換**: 技術用語や英単語は極力日本語のカタカナ表記に変換する
8. **キャラクターの口調**: 上の「現在のキャラクターと口調」に従う。口調は語尾や言い回しで表し、内容の正確さを優先する

### 英語のカタカナ変換ルール

VOICEVOXは英単語を正しく読めないことが多いため、英語は日本語のカタカナに変換してから読み上げます。

**変換例**:
- "build" → 「ビルド」
- "test" → 「テスト」
- "error" → 「エラー」
- "TypeScript" → 「タイプスクリプト」
- "API" → 「エーピーアイ」
- "Docker" → 「ドッカー」
- "GitHub" → 「ギットハブ」

**推奨アプローチ**:
- 一般的なIT用語は日本語で定着しているカタカナ表記を使用
- 例: "compile" → 「コンパイル」、"debug" → 「デバッグ」
- 可能であれば日本語の単語を優先（例: "start" → 「開始」、"finish" → 「完了」）

## vvsayコマンドの使用方法

- **`--bg`フラグでバックグラウンド実行**: 音声読み上げの完了を待たずに次の作業を続けるため、常に`--bg`フラグを付ける
- **`--queue`フラグで順番を保つ**: 前の報告が鳴り終わってから次を読み上げ、報告の順番が入れ替わったり重なったりしないようにする
- **それ以外のオプションは使用しない**: キャラクターや声の調整（`-n`, `-s`, `-p`, `--speed`など）は vvsay の設定に任せる
- **唯一の実行形式**:

```bash
vvsay --bg --queue "報告文"
```

この形式以外は使用しないでください。具体的な作業内容を含めることが重要です。
